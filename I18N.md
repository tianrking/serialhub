# Interface localization

SerialHub defaults to **English**. The language selector also provides **繁體中文**
(`zh-Hant`), **Español** (`es`), **Français** (`fr`), **العربية** (`ar`), and the
existing **简体中文** (`zh-Hans`) interface. Selection is explicit; the browser's
preferred language does not silently change the default.

The selector is in the top status area. A change applies without reloading the
page, reconnecting the Hub, clearing drafts, changing a lease or sending commands.
It is saved under `serialhub.ui.locale.v1` in this origin's local storage and
shared with other tabs of the same origin. If storage is unavailable, switching
still works for the current page. Clearing the preference restores the configured
default.

## Deployment controls

Copy `web/.env.example` to `web/.env.local`, or set the Vite build variables:

```bash
VITE_I18N_DEFAULT_LOCALE=en \
VITE_I18N_ENABLED_LOCALES=en,zh-Hant,es,fr,ar \
npm --prefix web run build
cargo build --locked --release --bins
```

PowerShell equivalent:

```powershell
$env:VITE_I18N_DEFAULT_LOCALE = 'en'
$env:VITE_I18N_ENABLED_LOCALES = 'en,zh-Hant,es,fr,ar'
npm --prefix web run build
cargo build --locked --release --bins
```

These are **build-time** settings: the release binary embeds the resulting web
assets. Setting them only when starting an already built binary does not alter
its interface policy. `npm run dev` reads the same Vite variables.

Only enabled locales appear in the selector. An old saved preference cannot
select a disabled locale. Duplicate locale IDs are removed; `zh-TW`/`zh-HK`
normalize to `zh-Hant`, and `zh-CN` to `zh-Hans`. A default outside the enabled
list resolves to the first enabled locale. An explicitly configured list with no
recognized IDs falls back to English; an unset list enables all supported locales.

## Text and data boundaries

- Translations are explicit, typed resource calls, not a DOM text-replacement
  overlay. Catalogs contain plain text; parameters are interpolated literally
  and React escapes their display.
- UI labels, validation, accessibility labels, dialogs and embedded help use the
  catalogs. Known static internal status messages follow the selected language.
  Previously generated operation-log entries and notifications retain their
  original wording rather than rewriting historical evidence.
- User-authored command names, payloads, device RX, backend diagnostic messages,
  protocol identifiers, event schemas and imported data retain their original
  values. Repository Markdown documentation is maintained separately from the
  embedded help; this change does not translate every document or backend message.
- Display counters, timestamps and chart values use locale-aware formatting.
  Arabic explicitly uses the `arab` numbering system so different CLDR versions
  agree. Serial commands, frame headers, numeric inputs, SVG coordinates, CSV
  numbers and JSON settings keep machine-compatible formats.
- Arabic sets `html[dir=rtl]`; workspace flow mirrors, while code, Hex, addresses,
  numeric input and plots retain their logical left-to-right order. Moving a
  curve or switching a language never changes the transmitted bytes.
- Catalogs are bundled with the application in a separate local asset. Language
  switching requires no translation service, external CDN or additional network
  request. Retain the complete `web/dist` when packaging or deploying.

## Maintaining translations

`web/src/i18n/locales/en.ts` defines the canonical, readable English message keys.
Every other catalog must satisfy the same TypeScript `Catalog` type. Add or
update the corresponding entry in **all six catalogs**, preserving interpolation
tokens such as `{p0}`. Taiwan-style Traditional Chinese uses terms including
`裝置`, `串列埠`, `參數`, `權杖` and `設定`.

Use `t("Connect to Hub")` for a label and
`t("Copied: {p0}", { p0: address })` for a complete parameterized message. Keep
validation state as booleans/codes; do not decide whether an operation is allowed
by comparing translated error text. Use `useLocale()` inside a memoized child
that displays localized text, and include the locale in calculations that cache
localized output.

```bash
npm --prefix web run check:i18n
npm --prefix web run lint
npm --prefix web test
npm --prefix web run build
PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium npm --prefix web run test:e2e
```

The catalog check rejects missing/extra keys, empty values, changed interpolation
tokens and hardcoded Chinese UI literals outside the i18n resources. Unit tests
cover policy, aliases, literal interpolation, formatting and invariant command /
CSV / configuration bytes. Browser tests cover all five requested languages,
RTL, desktop and mobile layout, persistence, cross-tab changes, blocked storage,
real mock UTF-8 traffic and switching during an acknowledged write. Existing
wire/safety regressions explicitly retain the original Simplified Chinese fixture
language; new localization tests start from the product's English default.

Automated checks establish coverage and behavior. Native-language terminology
review and validation on target operating systems remain part of release
acceptance; mock tests do not establish hardware qualification.
